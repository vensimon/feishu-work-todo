# 使用者自己的启停入口

## 从哪里打开

1.2及以后初始化完成后，桌面有“飞书待办控制台”。双击会在本机浏览器打开个人页面；无需保持AI对话打开才能点击开关。

安装包内也提供：macOS双击 `Open-Control-Panel.command`；Windows双击 `Open-Control-Panel.cmd`；Linux运行 `Open-Control-Panel.sh`。依赖已安装的Python。桌面入口使用初始化时记录的Python、个人profile和运行目录，能在安装包移动后继续打开。

需要补建入口时，让本人的AI运行 `python3 scripts/control_panel.py install-entry`。打开入口或查看状态不执行启停，不创建待办或重新授权。

## 两个按钮做什么

- 开启助手：开启当前个人安装的业务开关，按本人的授权启动卡片接收端；恢复后续已配置任务的工作。接收尚未连接、卡片尚未验证或定时尚未登记时如实展示，不把开关开启说成所有配置已完成。
- 关闭助手：阻止新聊天扫描、提案写入、通知发送和卡片勾选保存，停止当前安装的接收进程及其子进程，并关闭其登录启动项。保留表格、仪表盘、所有待办和历史记录。

控制台服务与卡片接收端独立，因此关掉接收端之后仍可从同一入口开启。关闭浏览器页面不等于关闭助手。控制台仅监听127.0.0.1，每次启动使用随机端口及本机校验令牌，不把个人数据发送到GitHub。

## 定时与进行中的请求

本机总开关不直接修改各AI宿主的调度器。原任务可能仍被唤起，但必须先读取enabled并直接跳过，不进行业务扫描或发送；若使用者还想停止宿主唤起与相应模型使用，应自行在对应AI客户端暂停定时任务。重新开启同样不会新建、恢复或重复创建宿主定时任务。

正在等待10点发送的脚本会检查关闭状态并取消。关闭后再开启也不会让已取消的旧轮次继续发送。已进入外部服务的请求可能先返回，关闭不能撤回已经送达的消息或回滚已确认的操作。

## 从旧版升级

此功能需要程序更新，不能仅靠修改GitHub在线样式出现。替换到1.2安装包后，保留自己的应用数据目录，让AI运行install-entry生成个人入口；首次点击开关会使用新版接收程序。旧的定时任务正文须加入“先读control_panel.py status，关闭时直接结束”，不能只换包却继续执行绕过入口的旧自定义流程。

不要把维护者以前的个人接收程序或旧profile迁给同事。本控制台只认当前个人安装；维护者原有系统不会因别人开关而变化。

## 验证范围

本版本验证了隔离数据的HTTP启停、越权请求拒绝、关闭后的业务拦截、闲置接收子进程退出，以及浏览器按钮和刷新后状态保留。未宣称三种AI客户端的独立账号流程均已验收，Windows任务策略和不同Linux桌面仍需目标环境验证。
