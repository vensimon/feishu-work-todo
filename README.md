# 飞书工作待办助手

**聊天里的工作，变成清楚的待办。**

从当前使用者自己的工作群和真人私聊中整理事项，区分“由你执行／确认／复核”等职责。配置完成后，工作日每天10点私聊发一张清单，多项勾选后一次确认，状态留在本人的多维表格中。

当前版本 **1.1.0 · 试用版**，支持GitHub在线同步提取规则和卡片样式。每人使用自己的授权、应用、待办表和接收进程，仓库只存通用程序与配置。

## 快速入口

- **给同事安装**：[安装说明](docs/installation.md)，下载本项目Releases中的技能ZIP。
- **你要改规则和样式**：[编辑 live/config.json](live/config.json)，按[维护说明](docs/online-configuration.md)操作。
- **查看完整技能**：[SKILL.md](skills/feishu-work-todo/SKILL.md)。
- **更新记录**：[CHANGELOG.md](CHANGELOG.md)。

## 功能

- 默认首次读取近15天，以后从上次成功水位增量读取并回溯48小时，读取前排除话题群。
- 新事项与所有未完成事项合并；未完成不因超过15天被删除。
- 区分“本人职责”和“进展”，别人执行、本人复核时只提醒本人复核这一环。
- 彩色职责标签、简洁名称、截止日期和下一步；一条清单多选确认。
- 个人台账、按日/月/职责分类视图、每日/每周趋势和长期未处理区。
- 保留完成记录与原消息证据；提取过程不自动替本人确认完成。

## 改一次，下一次运行同步

```mermaid
flowchart LR
    A[维护者编辑GitHub配置] --> B[各自运行时检查更新]
    B --> C[AI读取有效提取规则]
    B --> D[渲染器应用卡片样式]
    C --> E[各自的飞书待办与通知]
    D --> E
```

编辑 `live/config.json` 后提交到绑定分支即可。每次整理前读取新版规则，每次生成通知前检查新版样式；错误或断网时沿用最近有效版本。修改后无需逐个给同事发新包，也不修改他们的账号、完成记录或个人偏好。

**1.0用户需要升级一次到1.1。** 本机制更新的是配置，不自动下载执行远程程序；新增程序能力、修改表结构或定时唤起时间仍按升级/调度流程办理。旧卡片不自动重排或重复发送。

## 安装后对AI说

> 使用feishu-work-todo技能，初始化我自己的飞书工作待办助手。引导我授权本人账号，创建个人台账和仪表盘，验证消息中的批量勾选保存。按在线配置提取我的工作待办，排除话题群。配置并核验工作日每天北京时间10点向我本人私聊发送清单；未实际启用的能力请明确说明。

支持通过Kiro本地技能导入或豆包工作的技能入口安装。Python 3.9+与飞书CLI是运行依赖；首次本人授权、应用回调、接收进程和宿主定时能力需逐项验证。技能导入不等于定时已开通。

## 文件结构

```text
live/config.json                   日常在线修改入口
skills/feishu-work-todo/            可导入的完整技能
  SKILL.md                         AI工作入口与边界
  scripts/                         收集、台账、卡片、同步与初始化程序
  assets/                          空白表结构、内置默认、更新源
  references/                      安装、每日规则、输入协议与在线更新
docs/                              给使用者与维护者的说明
tests/                             不连接真实飞书的离线验证
tools/                             配置检查和发布包生成
.github/workflows/ci.yml            自动检查、测试与安装包构建
```

## 开发与检查

```sh
python3 -B tools/check.py
python3 -B -m unittest discover -s tests -v
python3 -B tools/build_release.py
```

运行程序只需Python标准库。测试不调用真实飞书或真实GitHub，不在仓库内保存使用者数据。当前有26项离线测试；仍需在目标Kiro/豆包工作环境验收，Windows登录任务需在目标系统验证。

更多见[开发约定](CONTRIBUTING.md)、[数据边界](SECURITY.md)与[部署方式](docs/architecture.md)。
