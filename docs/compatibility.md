# 兼容性与实际验收状态

核验日期：2026-11-17。版本：1.1.0试用版。

**官方支持技能、代码测试通过、真实业务全程验收是三种不同的证据。本项目尚未在三种宿主中分别使用新用户独立账号完成全流程验收，不应宣传为三端开箱即用。**

## 已完成的验证

- 26项离线程序测试，包括身份隔离、完成状态保护、手工编辑保留、多选回传处理、初始化幂等与配置回退；外部服务使用模拟响应。
- GitHub Actions上的Python 3.9与3.13检查、测试和ZIP构建。
- 实际免登录访问公开仓库、发布页、安装包，下载校验值与本地包一致。
- 在隔离临时目录中实际获取GitHub配置：私有API读取与公开Raw读取均验证；不涉及飞书工作数据。

这些验证不能证明新用户的企业授权、目标客户端执行工具、后台进程或定时任务一定可用。

## 分平台状态

| 宿主 | 官方能力依据 | 本项目尚缺的实测 |
| --- | --- | --- |
| Codex本地客户端 | 官方支持本地SKILL.md技能与可结合技能的定时任务；需要本地文件时，电脑和桌面应用须保持可用 | 从干净技能安装开始，使用独立飞书身份初始化、收集、提交和真实定时验收；后台任务的网络与文件访问策略也须验证 |
| Kiro本地IDE/CLI | 官方支持Agent Skills与本地文件夹导入；CLI headless需自身的KIRO_API_KEY及执行权限 | 实际导入当前ZIP中的技能目录；独立授权、后台接收、已安装CLI与操作系统调度的完整连接；没有对应CLI时不能假称已可无人值守 |
| 豆包工作 | 官方支持自定义技能、本地技能文件导入和定时任务；定时任务被描述为云端执行 | 当前技能的具体导入格式；执行环境是否有兼容lark-cli、Python、本人profile、持久状态；云端定时如何访问本地接收进程，或是否需要独立云端适配 |

当前包的接收进程使用macOS LaunchAgent，另提供待目标环境验证的Windows登录任务路径。Linux需单独配置用户服务。本项目尚未用Windows或Linux真实登录环境验收这些路径。不能把“Python测试在Linux通过”当作“Linux后台部署已验证”。

Codex云端、Kiro Web、普通豆包聊天和豆包工作的不同入口，不自动与本地桌面环境等同。客户端版本、登录身份和企业策略必须分别记录。

## 每个平台的验收标准

使用独立使用者自己的授权和测试资源，保留脱敏的时间、客户端版本及结果：

1. 导入后技能可被找到，运行入口正确，依赖检查明确报告Python、lark-cli和profile状态。
2. 本人完成授权后，能创建自己的空白台账、分类视图与仪表盘；不引用维护者资源。
3. 在本人同意的有限消息范围中扫描；话题群在读取前被排除；每项待办有实际证据和明确本人职责。
4. 自己收到验证卡片，点击后，接收进程有保存记录且原卡片确实更新；不通过勾完真实工作来测试。
5. 实际工作清单选择部分事项后，只有选中项变成完成；再次提交不重复记账；未选和手工编辑保留。
6. 通过宿主真实调度创建一个近期的一次性测试任务，让它在无人继续对话时运行；检查读取身份、持久状态、消息发送与回调，不能只读到一个任务ID就宣告成功。
7. 核验工作日10点的正式任务与下一次真实运行记录。测试时钟任务通过，不代表电脑离线时也能运行。
8. 维护者提交一项无业务影响的显示配置变更，该使用者同步后生成预览能看到变化；个人数据和偏好未被覆盖。

结果填写“通过／失败／待验证”和具体证据。尚未执行的项目不得填写通过；仅有官方说明时填写“有能力依据、待项目实测”。

## 当前能承诺的使用说明

可以分发独立的试用技能及在线配置源；使用者的数据与维护者分开保存。首次安装须按目标宿主逐项验证。当前不能承诺三种宿主或任意电脑都能一遍安装成功，也不能承诺无需权限配置即可稳定每日发送。
