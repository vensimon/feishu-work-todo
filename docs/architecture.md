# 结构与部署

程序分成三个部分：

1. GitHub只保存通用源代码、配置和说明；默认运行时只GET读取一个配置文件。
2. 每位使用者的AI宿主读取自己的聊天证据、应用有效规则并整理提案；脚本用其自己的CLI profile写入个人台账。
3. 每位使用者自己的接收进程处理本人在已登记卡片中的提交；飞书原生工作流与公式维护统计。

运行状态、证据、卡片映射和日志在每人自己的应用数据目录，凭证由本人的CLI或宿主环境管理。GitHub不会运行每日聊天分析，也不接收个人聊天或待办数据。仓库不是多人后台服务。

同一飞书应用的多个独立长连接接收端可能争抢事件，因此不同同事应使用独立应用/接收端。统一共享应用需要另建按用户路由的托管服务，不属于本版本。默认本地运行时，各自电脑离线期间不能收取提交或执行扫描。

配置同步与业务状态分开：online_config只更新缓存、有效规则和样式；不会写入state或Base。公共配置从GitHub取得后先验证再原子替换。个人偏好覆盖公共默认；同一源上一有效配置可回退。

程序不自动执行远程代码。对话中的工作证据与远程提取指导都不能改变客户端身份隔离、完成确认、授权范围及收件人。
